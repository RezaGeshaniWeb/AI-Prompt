1. Root cause explanation

The issue is on this line:

```javascript
for (let i = 0; i <= items.length; i++) {
```

Array indexes range from `0` to `items.length - 1`. Using `<=` makes the loop run one extra time when:

```javascript
i === items.length
```

At that point:

```javascript
items[i] // undefined
```

Therefore, this expression is invalid:

```javascript
items[i].price
```

With the exact code shown, JavaScript normally throws:

```text
TypeError: Cannot read properties of undefined (reading 'price')
```

It does not normally return `NaN`. `NaN` could occur in a related case where an item exists but its `price` is `undefined` or not a valid number.

2. Fix

Use `<` instead of `<=`:

```javascript
function calculateTotal(items) {
    let total = 0;

    for (let i = 0; i < items.length; i++) {
        total += items[i].price;
    }

    return total;
}

const cart = [
    { name: "Book", price: 10 },
    { name: "Pen", price: 2 }
];

console.log(calculateTotal(cart)); // 12
```

3. Improved version

Using `reduce()` is a concise and idiomatic approach:

```javascript
function calculateTotal(items) {
    return items.reduce((total, item) => total + item.price, 0);
}

const cart = [
    { name: "Book", price: 10 },
    { name: "Pen", price: 2 }
];

console.log(calculateTotal(cart)); // 12
```

If prices may be missing or invalid, add validation:

```javascript
function calculateTotal(items) {
    return items.reduce((total, item) => {
        const price = Number(item?.price);

        return total + (Number.isFinite(price) ? price : 0);
    }, 0);
}
```

This version safely handles missing items or invalid prices instead of producing an incorrect result.
