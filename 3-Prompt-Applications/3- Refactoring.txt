2. Refactoring strategy
Rename the function and parameter to describe their purpose.
Use filter() to retain only active items.
Use map() to create transformed output objects.
Replace loose equality (==) with strict equality (===).
Use arrow functions and implicit returns where readability remains clear.
Keep the output behavior unchanged:
inactive records are excluded;
active records retain only id, name, and transformed value;
value is multiplied by 2.

3. Refactored code
javascript
function transformActiveItems(items) {
    return items
        .filter(item => item.active === true)
        .map(({ id, name, value }) => ({
            id,
            name,
            value: value * 2
        }));
}

const input = [
    { id: 1, name: "A", value: 10, active: true },
    { id: 2, name: "B", value: 20, active: false },
    { id: 3, name: "C", value: 30, active: true }
];

console.log(transformActiveItems(input));
Output remains identical:

javascript
[
    { id: 1, name: "A", value: 20 },
    { id: 3, name: "C", value: 60 }
]

4. Short explanation of improvements
Clearer naming: transformActiveItems explains what the function does.
Declarative logic: filter() expresses selection; map() expresses transformation.
No manual mutation: Removes result.push() and the temporary obj variable.
Strict comparison: item.active === true avoids unwanted type coercion.
Destructuring: Extracts only the fields needed for the output.
Same behavior: Active items are returned with value doubled; inactive items are omitted.
